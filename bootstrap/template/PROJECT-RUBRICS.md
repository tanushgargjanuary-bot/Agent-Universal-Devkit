# Project Quality Rubrics — Agent Entry Point

This repository is connected to Agent-Universal-Devkit.

**Before major planning, architecture, implementation, or review work, read the canonical rubric file:**

https://github.com/tanushgargjanuary-bot/Agent-Universal-Devkit/blob/main/rubrics/PROJECT-RUBRICS.md

Then:

1. Identify the project's primary and secondary types from its actual purpose and repository evidence.
2. Apply the universal rubric and only the relevant domain rubrics.
3. Create or update `docs/QUALITY-RUBRICS.md` in this repository. Record selected profiles, critical criteria, project-specific thresholds, evidence, exceptions, and status.
4. Translate applicable criteria into requirements, design decisions, tasks, and tests.
5. During review, require evidence. Never mark a criterion as passed because an agent says it passed.
6. Reassess the selection when scope changes.

A project can use multiple profiles. For example, a cybersecurity research platform uses both cybersecurity and research criteria.

Do not copy every rubric into every project. Keep this file as the local entry point and load the canonical rubric when needed.

The universal criteria include simplicity, maintainability, flexibility, security, correctness, reliability, usability, testability, documentation, cost, and compatibility. Domain profiles add specialist criteria such as threat modelling, source citation, reproducibility, model evaluation, physical safety, or financial reconciliation.

If the canonical file cannot be accessed, state that limitation. Do not invent its contents.

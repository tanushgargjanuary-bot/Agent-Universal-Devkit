# Roadmap

## Phase 1 — Foundation
- [x] Establish repository structure.
- [x] Define central architecture.
- [x] Define bootstrap pointer format.
- [x] Define catalog schemas.
- [ ] Add validation tests.

## Phase 2 — Bootstrap and agent adapters
- [ ] Complete the reusable bootstrap payload.
- [ ] Add tested adapters for OpenCode, Claude Code, Codex, Gemini CLI, Antigravity, Cursor, and GitHub Copilot.
- [ ] Document each harness's native discovery behavior.
- [ ] Add a local bootstrap validator.

## Phase 3 — Tool catalog
- [ ] Add code review and static analysis tools.
- [ ] Add security and dependency scanning tools.
- [ ] Add testing and browser automation tools.
- [ ] Add web application starter kits.
- [ ] Add performance and profiling tools.
- [ ] Add AI/ML development tools.
- [ ] Review licenses and maintenance signals for every entry.

## Phase 4 — Automatic GitHub distribution
- [ ] Design a least-privilege GitHub App.
- [ ] Handle repository-created events.
- [ ] Install or repair bootstrap files idempotently.
- [ ] Maintain an opt-out mechanism.
- [ ] Test private and public repository behavior.

## Phase 5 — Intelligence and updates
- [ ] Detect project languages and frameworks.
- [ ] Recommend relevant tools.
- [ ] Monitor harness releases.
- [ ] Generate compatibility update pull requests.
- [ ] Test adapters against pinned harness versions.
- [ ] Offer controlled migration updates to existing repositories.

## Release rule

A capability is not complete until it has tests, documentation, and a clear security model.

- [x] Establish repository structure and core rules.
- [x] Define architecture and bootstrap pointer format.
- [x] Define tool, skill, and harness catalogs.
- [x] Define orchestration task schema and safety policy.

## Phase 2 — Bootstrap distribution
- [x] Create a small internal bootstrap payload.

## Phase 3 — Orchestration
- [x] Define task lifecycle and orchestration contract.
- [x] Define risk and approval policy.
- [ ] Build project inspection and task planner.

- [ ] Build independent result verification and run history.

## Phase 4 — Agent adapters and tool catalog
- [ ] Add tested adapters for OpenCode, Claude Code, Codex, Gemini CLI, Antigravity, Cursor, and GitHub Copilot.

- [ ] Add security and dependency scanning tools.
- [ ] Add testing and browser automation tools.
- [ ] Add web application starter kits.
- [ ] Add performance, profiling, and AI/ML tools.
- [ ] Review licenses and maintenance signals for every entry.

## Phase 5 — Intelligence and updates
- [ ] Detect languages and frameworks.
- [ ] Recommend relevant tools.
- [ ] Monitor harness and tool releases.
- [ ] Generate compatibility update PRs.
- [ ] Test adapters against recorded versions.
- [ ] Offer controlled migrations to existing repositories.

A capability is not complete until it has tests, documentation, and a clear security model.

# Security Policy

## Supported versions

Security fixes apply to the latest code on the default branch. Older snapshots may not receive fixes.

## Reporting a vulnerability

**Do not publish credentials, exploit details, or unpatched vulnerability reports in public issues or pull requests.**

Use GitHub's **Security** tab and select **Report a vulnerability** when private vulnerability reporting is available for this repository. If that option is unavailable, contact the repository owner through the GitHub profile and ask for a private reporting channel. Do not include exploit details in the initial public message.

Include the affected path or component, impact, reproduction steps, and any safe proof of concept. Do not include real user data or live credentials.

## Credential exposure

If a credential may have been committed, revoke or rotate it immediately. Removing it from the latest commit is not sufficient because it may remain in Git history, forks, caches, or clones. Review audit logs and affected services for misuse.

## Scope and expectations

- Do not access, modify, or delete data that does not belong to you.
- Do not disrupt services or perform denial-of-service testing.
- Do not use social engineering or physical attacks.
- Give maintainers a reasonable opportunity to investigate and fix a report before public disclosure.

This policy does not promise a response time or bug bounty.
